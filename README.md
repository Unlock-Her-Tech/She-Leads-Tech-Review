## Where this repository fits

[📙 Theory](https://github.com/Unlock-Her-Tech/She-Leads-Tech-Theory) → [🩷 Practice](https://github.com/Unlock-Her-Tech/She-Leads-Tech-Practice) → **💚 Review**

Review is not another lesson and it is not simply a new problem set. It is where you return to something you previously learned or practised, test what you can recall without help and decide what needs revisiting.

## What we revisit

Each review connects back to at least one earlier resource:

- A **Theory session** when you need to recall a concept, explain why an approach works or compare complexities.
- A **Practice session** when you need to recognise a pattern, solve a problem again or correct a repeated mistake.
- Both Theory and Practice when a topic needs a complete knowledge check.

## How review works

Use this cycle for every topic:

1. **Recall** — Write down what you remember before opening Theory or Practice.
2. **Recognise** — Identify the clues that tell you which pattern or data structure to use.
3. **Explain** — Describe why the approach works and state its time and space complexity.
4. **Re-solve** — Return to one earlier Practice problem and solve it without viewing the solution.
5. **Check** — Compare your answer with the original notes or reference solution.
6. **Revisit** — Study only the parts you missed, then try again later without notes.

## Suggested review schedule

| When | Review action |
| --- | --- |
| After the session | Summarise the main idea in your own words |
| 1–2 days later | Complete a short recall check without notes |
| 1 week later | Re-solve one representative Practice problem |
| 2–4 weeks later | Explain the pattern and solve a mixed or interview-style problem |

Treat the schedule as guidance. Revisit a topic sooner when it still feels unclear.

## Review resource structure

Reviews are organised by topic rather than by event date:

~~~text
Leetcode-Typescript/
└── Topic-Name/
    ├── README.md
    ├── Quick-Check.md
    ├── Common-Mistakes.md
    └── Answers.md
~~~

- **README.md** links to the Theory and Practice sessions being revisited and explains the review goals.
- **Quick-Check.md** contains recall, recognition, reasoning and debugging questions.
- **Common-Mistakes.md** records mistakes learners are likely to repeat and how to recognise them.
- **Answers.md** keeps answers separate so learners can attempt the review first.

Only add files that a topic needs. A short review can use just a topic README and quick check.

## When a review is complete

You are ready to move on when you can:

- Explain the concept without copying the notes
- Recognise when the pattern applies
- Solve a representative problem without opening the solution
- State and justify the complexity
- Identify your earlier mistake and explain how you corrected it

If one of these is still difficult, return to the linked Theory explanation or Practice problem and repeat the review cycle.

## Contributing a review

Contributions should check existing knowledge rather than introduce a new topic.

1. Choose a Theory or Practice session that learners have already completed.
2. Create a topic folder with a clear, descriptive name.
3. Link directly to the material being revisited.
4. Write prompts that test recall, recognition, reasoning and debugging.
5. Keep answers separate from questions.
6. Check every link before opening a pull request.

Avoid copying full lessons or solutions into Review. Link to the source and focus on helping learners remember and apply it.
